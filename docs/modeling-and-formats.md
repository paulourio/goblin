# Modeling API and Serialization Formats

The `goblin` modeling layer provides a strongly typed Go API for constructing Linear Programs (`LP`) and Mixed-Integer Linear Programs (`MILP`), compiling them into encapsulated sparse matrices (`CompiledProblem`), and exchanging problem definitions with Python `PuLP` and standard MPS solvers.

---

## 1. Constructing Models (`Model`, `Var`, `Expr`, `Constraint`)

### Variables and Bounds
Create a model with [`NewModel(name, sense)`](../model.go), where `sense` is `Minimize` (`1`) or `Maximize` (`-1`). Passing an unrecognized `Sense` records a sticky validation error reported by `Validate()`, `CompileChecked()`, and `Solve()`. Variables are 64-bit handles (`type Var uint64`, encoding a non-zero 32-bit owning-model tag in the upper 32 bits and the 0-based column index in the lower 32 bits so `Var(0)` is never valid) registered via four methods on [`Model`](../model.go):
- `AddContVar(name string, lb, ub float64) Var`: Continuous variable $x_j \in [\text{lb}, \text{ub}]$. Use `math.Inf(-1)` and `math.Inf(1)` for unbounded sides.
- `AddIntVar(name string, lb, ub float64) Var`: General integer variable $x_j \in [\lceil \text{lb} \rceil, \lfloor \text{ub} \rfloor] \cap \mathbb{Z}$.
- `AddBinaryVar(name string) Var`: Binary variable $x_j \in \{0, 1\}$.
- `AddVar(name string, lb, ub float64, cat VarCategory) Var`: Generic constructor accepting `Continuous`, `Integer`, or `Binary`.
- Exact rational bounds `AddVarRat(name string, lb, ub *big.Rat, cat VarCategory) Var`, `AddContVarRat(name string, lb, ub *big.Rat) Var`, and `AddIntVarRat(name string, lb, ub *big.Rat) Var`: Opt-in constructors that defensively clone non-nil `*big.Rat` bounds (`nil` denotes $-\infty$ on `lb` or $+\infty$ on `ub`), retain nearest finite `float64` bounds for default solving, and preserve exact rational bounds for certification. Calling `SetVarBounds` resets rational bounds back to standard `float64` semantics.

```go
m := gb.NewModel("knapsack", gb.Maximize)
x := m.AddBinaryVar("x")
y := m.AddIntVar("y", 0, 10)
m.SetObjective(gb.NewExpr(x.T(12), y.T(7)))
m.AddConstraint("cap", gb.NewExpr(x.T(4), y.T(3)).Le(25))
```

When an empty string `""` is passed for a variable or constraint name, `Model` assigns a unique default identifier (`x_0`, `_C1`, etc.). If a subsequent variable or constraint explicitly claims that identifier, the auto-generated placeholder renames automatically; duplicate explicit names fail `Validate()`.

### Linear Expressions and Constraints
By convention, callers import `github.com/paulourio/goblin` as `gb` (`import gb "github.com/paulourio/goblin"`) for concise expression construction. Linear expressions (`Expr`) combine variable-coefficient pairs (`Term`) with an optional scalar constant:
- The method `v.T(coeff float64) Term` (or `T(v Var, coeff float64) Term`) constructs a single term $c_j x_j$.
- The function `NewExpr(terms ...Term) Expr` builds a linear expression $\sum_k c_k x_{v_k}$.
- The methods `expr.Le(rhs)`, `expr.Ge(rhs)`, and `expr.Eq(rhs)` (or `Le(expr, rhs)`, `Ge(expr, rhs)`, and `Eq(expr, rhs)`) construct `LessEqual` ($\le$), `GreaterEqual` ($\ge$), and `Equal` ($=$) constraints. Each constraint stores `RHS` and `Expr.Constant` separately in `Model` so compilation detects cancellation or rounding loss in `RHS - Expr.Constant` rather than folding early.
- Exact decimal and rational builders allow non-dyadic inputs (such as `0.9` or `-7.2`) without binary rounding error: `ParseExactRat(s string) (*big.Rat, error)` parses strict decimal or rational literals without whitespace or octal traps (rejecting non-finite strings, zero or signed denominators, and base-10 exponents exceeding `10000` in magnitude); `v.TRat(coeff *big.Rat) Term`, `TRat(v Var, coeff *big.Rat) Term`, and `v.TDec(decimal string) Term` construct exact terms (`TDec` and `nil` arguments record deferred validation errors without panicking); `(Expr).AddTermRat` and `(Expr).AddConstantRat` clone rational inputs defensively while propagating through `Sum` and `Scale`; and `LeRat`, `GeRat`, `EqRat` (both package functions and `Expr` methods) build constraints with exact rational right-hand sides. Standard `float64` builders leave internal rational pointers `nil` for zero overhead.
- The inner product helper `Dot(vars, coeffs)` constructs $\sum_i c_i x_i$ while omitting zero coefficients; if `len(vars) != len(coeffs)`, `Dot` records a deferred validation error (`"Dot: mismatched slice lengths"`) without panicking or silently truncating.

## 2. Model Validation and Sparse Matrix Compilation (`Model.Compile`)

Calling [`Model.Validate()`](../model.go) or [`Model.CompileChecked()`](../compiled.go) checks that the receiver `Model` is non-nil (`ErrNilModel`), uses a valid `Sense`, carries no deferred `Dot` slice-length mismatch, and that all variable bounds, objective terms, and constraint terms reference `Var` handles owned by the receiver `Model`, contain finite (`non-NaN`, `non-Inf`) individual and accumulated coefficients plus finite net right-hand sides (`c.RHS - c.Expr.Constant`), use a valid `VarCategory` (`Continuous`, `Integer`, or `Binary`), use unique explicit variable and constraint names, and use a valid `ConstraintSense` (`LessEqual`, `Equal`, or `GreaterEqual`). If an invalid model is passed directly to `Solve()` or `SolveCompiled()`, the solver returns `StatusUndefined` and the validation error. Bounds that become empty after integer rounding (for example an integer variable on `[0.5, 0.7]`) are not a validation error; the solver reports `StatusInfeasible`.

Calling [`Model.Compile()`](../compiled.go) freezes the algebraic model into an immutable [`CompiledProblem`](../compiled.go) exposed through read-only methods (`NumVars`, `NumConstraints`, `NNZ`, `IsMIP`, `VarBounds`, `VarCategory`, `RowSense`, `RowRHS`, `ForEachRowTerm`, `ForEachColTerm`, `Err`):
1. **Term Deduplication, Mode-Separated Float vs. Exact Rational Semantics**: Within the objective and each constraint row, duplicate references to the same `Var` are summed in preallocated accumulator slices (`rowAcc`, `touched`, `inTouched`) with wide-accumulator exactness checks (or exact `*big.Rat` sums when exact terms are present), overflowed sums are recorded on `invalidErr`, and only exact zero coefficients (`val == 0`) are dropped. Default uncertified mode (`WithCertified(false)` without `WithVIPRTrace`) evaluates all constraints uniformly using compiled IEEE-754 `float64(RHS - Expr.Constant)` and nearest `float64` bounds under solver tolerances, without compile-time sub-unit pure-integer RHS tightening or exact equality rejection, preserving parity with `PuLP`/`CBC`, `WriteMPS`, and `ToPuLPJSON`. Whenever float folding (`c.RHS - c.Expr.Constant`, objective constants, or duplicate-term sums) loses rational exactness, a pure-integer row has integer coefficients and a fractional net-RHS residual (`rhsLo != 0` or a non-integer exact rational RHS), or the model supplies exact `*big.Rat` bounds, terms, constants, or right-hand sides, `Compile` leaves `RowRHS` at the compiled `float64` value and attaches optional unmerged metadata (`nil` on exact `float64` models for zero overhead) recording the exact rationals, raw terms, constants, and `floor`/`ceil`/equality tightening rules. Those exact rational semantics (binary-dyadic $\mathbb{Q}$ for `float64` inputs, or full exact $\mathbb{Q}$ including base-10 $\mathbb{Q}_{10}$ decimals when supplied via the opt-in `*Rat`/`*Dec` or `FromPuLPJSONExact` APIs) activate only under `WithCertified(true)` or `WithVIPRTrace`, including exact `ceil`/`floor` integer variable bound tightening.
2. **Sorted `CSR` and Bounded Dense Row Construction**: Nonzero column indices within each row $i$ are sorted in ascending order and packed into `rowPtr`, `colIdx`, and `rowVal` arrays. When $n \le 256$ (`DenseThreshold`) and the dense buffer stays within `maxDenseRowFloats` ($2^{20}$ floats) and sparsity bounds, `Compile` also populates 64-byte-aligned `denseRows`.
3. **Transposed `CSC` Construction**: A two-pass counting transpose builds `colPtr`, `rowIdx`, `colVal`, and 32-bit `colPtr32`/`rowIdx32` views in $O(\text{nnz} + n + m)$ time.
4. **Integer Column Indexing**: Integer variables whose rounded bounds lie inside $[0, 1]$ are promoted to `Binary` in `CompiledProblem`, and all `Binary` and `Integer` variable indices are collected into `intCols`, setting `isMIP = len(intCols) > 0`.

Once compiled, a single `*CompiledProblem` can be solved repeatedly with different solver settings or across concurrent goroutines via [`SolveCompiled(ctx, p, opts...)`](../solve.go).

### Functional Solver Settings and Backends

Both `Model.Solve(ctx, opts...)` and `SolveCompiled(ctx, p, opts...)` accept a `context.Context` as their first parameter, start from the default pure-Go settings ([`solve.go`](../solve.go): `BackendGo`, presolve, cuts, heuristics, and SIMD enabled), apply functional [`Option`](../solve.go) values in order, and return `(Result, error)`:

- **Backend choice and pure-Go fallback (`Result.FellBackToGo`)**: `WithPureGo()` (`WithBackend(BackendGo)`, default) runs the pure-Go simplex and Branch-and-Cut engine without `cgo`; `WithCBC()` (`WithBackend(BackendCBC)`) dispatches the validated `CSC` matrix single-threaded to COIN-OR CBC/CLP via `cgo` (serialized process-wide across goroutines) when built with `-tags cbc` (or `-tags "cbc,cbc_system"` against system `pkg-config` COIN-OR libraries when importing the module outside a full repository checkout; otherwise `Solve` returns `StatusUndefined`). Whenever `BackendCBC` encounters severe scaling, cancellation, or spurious status anomalies, or whenever `WithCBC()` is combined with `WithCertified(true)` on a MILP (`IsMIP() == true`, since C++ CBC does not emit `VIPRTrace` certificates), execution delegates to the single-threaded compensated pure-Go engine while keeping `Result.Backend == BackendCBC` and setting `Result.FellBackToGo == true` so callers and differential harnesses can inspect whether native C++ CBC executed.
- **SIMD control**: `WithSIMD(bool)` and `WithoutSIMD()` toggle runtime AVX-512, AVX2, and scalar vector dispatch on the pure-Go backend.
- **Parallel search**: `WithWorkers(n)` configures the parallel Branch-and-Bound worker pool on `BackendGo` (`BackendCBC` ignores worker count and always runs single-threaded). Values `<= 1` run deterministically on a single thread by default.
- **Search and tolerance limits**: `WithTimeLimit(d)` (where `0` is unlimited and negative values terminate immediately with `StatusTimeLimit`), `WithMaxNodes(n)` (`DefaultOptions().MaxNodes = 50000`; pass `0` for unlimited), `WithMaxIter(n)`, `WithPresolve(bool)`, `WithCuts(bool)`, `WithHeuristics(bool)`, `WithMaxCutPasses(n)`, `WithRelGapTol(tol)` (measured on the linear objective `c^T x`), and `WithAbsGapTol(tol)`. Explicit `WithOptions`, `WithMaxNodes`, and `WithMaxCutPasses` overrides are honored identically across `BackendGo` and `BackendCBC`. Note that setting `Options{Certified: true}` inside a struct literal passed to `WithOptions` without also calling `WithCertified(true)` intentionally fails closed with `ErrCertificationFailed` (`StatusNumericalError`), because `WithCertified(true)` installs the internal verifier function pointer so binaries omitting `WithCertified` dead-code-eliminate the certification engine at link time.
- **Proof tracing and fail-closed certification**: Calling `WithVIPRTrace(tr)` records an exact rational Mini-VIPR proof tree (`NewVIPRTrace`) with presolve and orbital-symmetry envelopes on `BackendGo` (disabling LP presolve on pure LPs so the trace targets original `CompiledProblem`), checkable standalone via `VerifyVIPRTrace` under deterministic fallback work budgets (`100,000` LP iterations and `5,000` B&B nodes, with no wall-clock deadline). Passing `WithCertified(true)` or `WithVIPRTrace` activates exact $\mathbb{Q}$ semantics (including pure-integer fractional RHS and variable-bound tightening via `floor`/`ceil`, raw unmerged duplicate terms, exact `RHS - Expr.Constant`, and exact-$\mathbb{Q}$ equality checks against compiled binary-dyadic values or preserved `*big.Rat` inputs), whereas default uncertified mode evaluates compiled `float64(RHS - Expr.Constant)` uniformly under solver tolerances. This mode split explains why non-dyadic decimal equalities ingested as `float64` (such as `-7.2*x1 - 4.1*x2 = -1` or `miplib_flugpl` row `ANZ3`, where binary64 `0.9` equals $8106479329266893 / 2^{53}$) can be feasible under default float tolerances yet diverge in exact dyadic $\mathbb{Q}$ unless supplied via the opt-in `*Rat`/`*Dec` API or `FromPuLPJSONExact`. Passing `WithCertified(true)` proves optimality or bounds over $\mathbb{Q}$ in pure Go without invoking Lean at runtime (these pure-Go checkers carry no formal proof of their Go code and are validated offline against Lean 4 CLI checkers under `GOBLIN_FORMAL=1`). Callers needing unrounded `*big.Rat` witnesses can pass `gb.WithCertifiedWitness` (`CertifiedWitness`); otherwise `Result.Values` (for continuous variables), `Duals`, `ReducedCosts`, and `Objective` hold those exact rationals rounded to nearest `float64` ($\le 0.5\text{ ULP}$), integer coordinates stay exact, and `BestBound` rounds outward (`floor` for `Minimize`, `ceil` for `Maximize`). Rounded continuous `float64` `Result.Values` alone can therefore show up to `0.5`-ULP constraint residuals when re-evaluated in `float64` even when the internal exact witness satisfies the model with zero violation. If an exact witness fails or cannot be built, the solver clears unsafe output fields, sets `StatusNumericalError`, and returns `(res, ErrCertificationFailed)`. Note that `WithCertified(true)` and `gb.WithCertifiedWitness` require calling those option constructors rather than passing `Options{Certified: true}` via `WithOptions`, so binaries omitting them drop the certification engine at link time.
- **Variable value lookup**: `res.Lookup(v)` returns `(val, true)` when `v` belongs to the solved `Model` and an incumbent vector is present, or `(0, false)` on foreign handles and statuses without an incumbent; `res.Value(v)` returns `val` directly.
- **Termination codes**: `Status` codes `0`, `1`, `-1`, `-2`, and `-3` match `PuLP`'s `LpStatus` codes (`StatusNotSolved`, `StatusOptimal`, `StatusInfeasible`, `StatusUnbounded`, `StatusUndefined`); codes `-4` through `-12` extend that set for solver resource limits and numerical errors.
- **Context cancellation vs. solver time limit**: `ctx` handles upstream cancellation and service deadlines; when `ctx` is canceled or its deadline expires (including while waiting for the serialized `BackendCBC` semaphore), the solver aborts, discards partial solutions, and returns `(Result{}, ctx.Err())`. Conversely, `WithTimeLimit(d)` sets a solver time budget that returns `(res, nil)` with `res.Status == StatusTimeLimit` along with the best incumbent (`res.Values`, `res.Objective`) and global bound (`res.BestBound`) found so far.

```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

res, err := gb.SolveCompiled(ctx, p,
	gb.WithPureGo(),
	gb.WithTimeLimit(time.Second), // StatusTimeLimit when exceeded (retains best incumbent)
	gb.WithMaxNodes(10000),        // StatusNodeLimit when exceeded
	gb.WithMaxIter(200000),        // total simplex iterations; StatusIterationLimit when exceeded
)
if err != nil {
	return err
}
```

Whenever a solver resource limit (`WithTimeLimit`, `WithMaxNodes`, `WithMaxIter`) stops an LP or MILP search after a valid global dual bound has been established (after the root LP solves), `Result.BestBound` holds that global bound and `Result.Values` holds the best incumbent found, if any. Whenever a limit exit fires before a valid global dual bound is established (including pre-root exits and presolve/solver fallbacks), `Result.BestBound` is `-Inf` (`Minimize`) or `+Inf` (`Maximize`) with `Result.Objective = 0` when no incumbent exists, and `WithCertified(true)` accepts uncertified limit bounds only when matching that trivial infinite bound.

## 3. `PuLP` JSON Interoperability (`goblin/format`)

The [`format/pulp_json.go`](../format/pulp_json.go) file reads and writes Python `PuLP`'s `LpProblem.toJson()` / `LpProblem.fromJson()` schema:
- **Objective Offset and Constraint Sign Rule**: Objective scalar offsets round-trip across `goblin` via the `objective.constant` extension field (ignored by Python `PuLP`'s `LpProblem.fromJson`). In `PuLP`'s JSON dictionary, each constraint stores `coefficients` and a scalar `constant` representing $\sum_j a_{i,j} x_j + \text{constant} \ \{\le, =, \ge\}\ 0$, while omitted `"lowBound"` variable keys default to `0` (`null` maps to $-\infty$). The function [`BuildModelFromPuLPJSON`](../format/pulp_json.go) maps `RHS = -c.Constant` and validates `sense` codes (`-1` $\to$ `LessEqual`, `0` $\to$ `Equal`, `1` $\to$ `GreaterEqual`).
- **Validation Guards and Solution Field Tolerance**: [`BuildModelFromPuLPJSON`](../format/pulp_json.go) rejects empty or duplicate variable names, duplicate constraint names (auto-assigning unique `_C1`, `_C2`, ... identifiers when a constraint name is empty), non-finite structural bounds or coefficients, invalid `sense` or `cat` values, and non-empty `sos1` or `sos2` sets, while [`ParsePuLPJSON`](../format/pulp_json.go) tolerates Python's `NaN`, `Infinity`, and `-Infinity` tokens on ignored solution fields (`varValue`, `dj`, `pi`) and preserves negative zero (`-0.0`) signs.
- **Binary and Integer Bounds**: `PuLP` serializes binary variables as `"cat": "Integer"` with `"lowBound": 0, "upBound": 1`. During [`BuildModelFromPuLPJSON`](../format/pulp_json.go), `"cat": "Binary"` honors explicit `lowBound`/`upBound` overrides (defaulting to `[0, 1]` when omitted), and integer variables whose bounds lie within `[0, 1]` become `gb.Binary` so that 0-1 knapsack cover lifting and binary bound tightening activate automatically.
- **Direct Streaming and Separated Stages**: [`FromPuLPJSONBytes`](../format/pulp_json.go) and `FromPuLPJSON` route standard JSON payloads through [`fromPuLPJSONFast`](../format/pulp_json_fast.go), populating `*gb.Model` directly without allocating intermediate `PuLPJSON` AST slices and falling back automatically to `ParsePuLPJSON` + `BuildModelFromPuLPJSON` on escaped strings, duplicate keys, or out-of-order sections. Callers needing separate timing phases can still invoke `ParsePuLPJSON(data)` and `BuildModelFromPuLPJSON(doc)` explicitly.
- **Exact Rational JSON Ingestion**: [`FromPuLPJSONExactBytes`](../format/pulp_json.go) and [`FromPuLPJSONExact`](../format/pulp_json.go) parse JSON numeric tokens directly through `ParseExactRat` into `*big.Rat` variable bounds (`AddVarRat`), terms (`TRat`), objective constants (`AddConstantRat`), and constraint right-hand sides (`LeRat`, `GeRat`, `EqRat`), preserving base-10 non-dyadic coefficients (such as `0.9` in `miplib_flugpl` row `ANZ3`) for certification under `WithCertified(true)` and `WithVIPRTrace` while leaving `FromPuLPJSONBytes` and `FromPuLPJSON` unchanged on the default `float64` path.

## 4. MPS Serialization (`format.WriteMPS`)

The function [`format.WriteMPS(p *CompiledProblem, w io.Writer)`](../format/mps.go) emits MPS output from a valid `CompiledProblem` aligned to standard fixed-MPS column offsets (`5`, `15`, and `25` for identifiers up to 8 characters, space-separated when longer):
- Formats all floating-point coefficients, right-hand sides, and variable bounds losslessly via `strconv.FormatFloat(v, 'g', -1, 64)`, validates that variable and row names are unique, printable, whitespace-free, free of leading `$` or `*` comment characters, and distinct from the reserved `'MARKER'` token, rejects row names that collide with the objective row name, normalizes all conflicting `lb > ub` bounds (without a `1e-7` tolerance threshold) into an explicit infeasible `(0, 1)` `L` row so COIN-OR MPS parsers agree on sub-tolerance bound conflicts, and emits an explicit zero objective entry for any column absent from both the objective and all constraints.
- Writes `*SENSE:Minimize` or `*SENSE:Maximize` on line 1 as an MPS `*` comment card matching `PuLP` default `with_objsense=False` output (never `OBJSENSE`), followed by `NAME`, `ROWS` (`N` objective, `L`/`G`/`E` constraints), `COLUMNS` (iterating via `ForEachColTerm` and already negating `Maximize` objective coefficients $-c_j$ into standard MPS minimization form, while bracketing integer blocks with `'MARKER' 'INTORG'` and `'INTEND'`), `RHS` (already negating `Maximize` `ObjConstant` into minimization form alongside row right-hand sides), `BOUNDS`, and `ENDATA`. External MPS solvers (`cbc`, `highs`, `glpsol`) must therefore run in default minimization mode and must not pass `-max`, which double-negates `Maximize` models.

## 5. Linear Sum Assignment API (`goblin/assign`)

The [`goblin/assign`](../assign/assign.go) subpackage (and root aliases [`LinearSumAssignment`](../assign_alias.go) / [`LinearSumAssignmentFlat`](../assign_alias.go)) solves square and rectangular Linear Sum Assignment Problems (`LSAP`) without constructing an algebraic `Model`:

- [`assign.LinearSum(ctx context.Context, cost [][]float64, sense Sense, opts ...Option)`](../assign/assign.go): solves a 2D slice cost matrix of shape $m \times n$ under `assign.Minimize` (`1`) or `assign.Maximize` (`-1`), returning `RowInd`, `ColInd`, `Objective`, and dual potentials `U`, `V`.
- [`assign.LinearSumFlat(ctx context.Context, rows, cols int, cost []float64, sense Sense, opts ...Option)`](../assign/assign.go): solves a contiguous row-major slice (`cost[i*cols + j]`).
- [`assign.SolveInto(ctx context.Context, rows, cols int, cost []float64, sense Sense, rowInd, colInd []int, ws *Workspace, opts ...Option)`](../assign/assign.go): zero-allocation hot-loop entry point writing matches directly into caller slices over a pooled [`assign.Workspace`](../assign/workspace.go) (`AcquireWorkspace` / `ReleaseWorkspace`). When `ctx` is canceled or its deadline expires, the solver returns `ctx.Err()`.
- **Forbidden Edges, Certified Mode, and Errors**: under `Minimize`, entries set to `+Inf` (`-Inf` under `Maximize`) mark forbidden pairs $(i, j)$ that cannot be selected. Passing `assign.WithCertified(true)` runs pure-Go checking in-process over exact 2304-bit dyadic rationals (`dyadic2304`, without invoking Lean at runtime; `assign/certified.go` carries no formal proof of its Go code and is validated differentially against Lean 4 `lsap-check` under `GOBLIN_FORMAL=1`) to confirm global optimality or build and check a bipartite Hall subset on `ErrInfeasible`. Under `assign.WithCertified(true)`, `Result.Objective` holds the nearest `float64` ($\le 0.5\text{ ULP}$) to the exact dyadic sum, while `Result.U` and `Result.V` hold finite `float64` dual potentials floored when necessary so $U_i + V_j \le C_{ij}$ holds over $\mathbb{Q}$. Any failure returns `assign.ErrCertificationFailed` while preserving `0` allocations on `SolveInto` and `0` linked checker bytes when unreferenced. The solver returns [`ErrInvalidDimensions`](../assign/assign.go) on negative or mismatched slice dimensions, [`ErrInvalidCost`](../assign/assign.go) on `NaN` or unbounded `-Inf` (`+Inf` under `Maximize`) entries, and [`ErrInfeasible`](../assign/assign.go) when no finite matching of size $k = \min(m, n)$ exists.

## 6. Automatic Combinatorial MAD Search (`WithCombinatorialSearch`)

Default `Model.Solve` and `SolveCompiled` on `BackendGo` automatically detect closed separable group-item L1/MAD allocation models via [`mad_detect.go`](../mad_detect.go) and delegate them to the internal [`internal/mad`](../internal/mad/mad.go) engine without changing the algebraic modeling API:

- **Zero-allocation pre-screen and strict closure**: Non-MAD LPs and MILPs reject with zero heap allocations on the first incompatible variable or row count. Accepted models must have 100% variable, bound, row, and objective closure (partition equality rows $\sum_g x_{g,i} = 1$, optional bijective designated-item rows, matching opposite-sign L1 epigraph pairs $z_{g,t} \ge |a_{g,t} + \sum_i d_{i,t} x_{g,i} - m_g|$, and optional roundness penalties $r_g \ge |m_g - B n_g|$ or direct-step substitution $m_g = B n_g$).
- **Transparent Branch-and-Cut fallback**: Models that exceed combinatorial work or memory caps (`MaxDPItems = 14`, `MaxDPWork = 64_000_000`, `MaxDPBytes = 32 << 20`, `MaxDFSStates = 250_000`), contain binding finite bounds on $m_g$ or $n_g$, use `WithCBC()`, or request an explicit `WithVIPRTrace` proof fall straight through to normal presolve and Branch-and-Cut. Passing `gb.WithCombinatorialSearch(false)` disables combinatorial detection explicitly (used by the 31-family pure Branch-and-Cut benchmark suite and negative-control tests).
- **Double-double oracle and certified mode**: Uncertified solves run `twoSum`/`twoProd` (`math.FMA`) double-double DFS or subset bitmask DP with zero `math/big` symbols linked into default binaries. Passing `gb.WithCertified(true)` or `gb.WithCertifiedWitness` (without `WithVIPRTrace`) runs exact fixed-width `uint64`-limb dyadic DP (`internal/mad/certified.go`) followed by exact `*big.Rat` primal and objective verification against the original `CompiledProblem`.
